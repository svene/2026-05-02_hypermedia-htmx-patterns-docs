## 3. Custom Page

Custom Page taking a parameter. When the default content page does not fit.

<iframe width="100%" style="min-height: 100px" scrolling="no" src="http://localhost:3000/s03/d03"></iframe>
[Demo](http://localhost:3000/s03/d03)

Recommended for special case pages of an application.
This page-component does not use a layout component.
Instead it constructs a page by including the common parts like header, navigation and footer itself.

So this component has an active role in the process of constructing a page, not a passive one as
in the Content-Page Pattern.

In the Content-Page Pattern the layout (including header, navigation and footer) is reusable.
In this Custom-Page Pattern only the parts (header, navigation, footer) are reusable.

## 4. MPA Example

Multi Page Application with a menu

<iframe width="100%" style="min-height: 300px" scrolling="no" src="http://localhost:3000/s03/d04p1"></iframe>
[Demo](http://localhost:3000/s03/d04p1)

The pages of this application all use a common layout component (the template).

In contrast to the Inclusion Pattern the __layout__ component __plays an active role__
in the template process because it pulls in the component.
The component plays the passive role.
Therefore it is the layout which uses the injection pattern, not the component.

Since the components are injected into the layout dynamically
it can be reused for all pages of the application.

For this demo the injected component-content is surrounded with a colored border
to show what is coming from the layout and what is coming from the component.
Everything outside the border is coming from the layout template.
Everything inside is comping from the injected component.
